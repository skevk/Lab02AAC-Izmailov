## Результаты замера Debug vs Release

| Режим | Запуск 1 | Запуск 2 | Запуск 3 | Запуск 4 | Запуск 5 | Минимум |
| ------- | -------: | -------: | -------: | -------: | -------: | ------: |
| Debug | 1503 мс | 1499 мс | 1494 мс | 1497 мс | 1490 мс | 1490 мс |
| Release | 200 мс | 197 мс | 200 мс | 198 мс | 199 мс | 197 мс |

В моём эксперименте Release оказался быстрее Debug примерно в 7.5 раза.

Что я обнаружил при сравнении IL

• в Debug присутствуют инструкции nop, которых нет в Release;
• в Release уменьшилось количество промежуточных операций с локальными
переменными;
• количество IL-инструкций в методе Add() изменилось с 10 до 4.

## Ответы на контрольные вопросы

1. IL-код — промежуточный код, который появляется после компиляции C#-
программы.IL позволяет отделить исходный код от конкретной архитектуры процессора. При
запуске JIT-компилятор преобразует IL в подходящие машинные инструкции.

2. Потому что .dll содержит не машинный код, а IL и метаданные.

3. В Debug есть инструкция nop.

4. Потому что в Release компилятор больше оптимизирует код.

5.  Потому что обычные строки
хранятся как текст, без шифрования.
